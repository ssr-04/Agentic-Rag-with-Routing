# Folder Structure Analysis Report

## Summary
This codebase implements an Agentic Retrieval-Augmented Generation (RAG) system organized in a phased approach. The project has a simple, clear folder structure with a two-phase implementation design. Phase 1 focuses on document processing and indexing, while Phase 2 implements the intelligent query processing and response generation system. The codebase is organized in a functional manner with clear separation between phases.

## Directory Layout
- `/Phase-1`: Contains the implementation for Phase 1 of the RAG system, focusing on document ingestion, processing, and indexing.
  - `phase1_build.py`: Script for building the RAG pipeline - extracting text from PDFs, chunking, embedding, and creating FAISS and BM25 indexes.
- `agentic_rag_phase2.py`: Main implementation for Phase 2 of the RAG system - the agentic query processing, retrieval, and answer generation.
- `README.md`: Documentation describing the project, features, prerequisites, installation, and configuration.

## Expected Runtime Directories (not present in repository but referenced in code)
- `/cache`: Directory for storing processed data and indexes
  - `chunks.json`: Cached document chunks
  - `embeddings.json`: Cached embeddings
  - `faiss_index.bin`: FAISS vector index
  - `faiss_metadata.json`: Metadata mapping for FAISS index
  - `bm25_index.pkl`: Serialized BM25 index
- `/docs`: Directory for source PDF documents to be processed

## Observed Patterns
1. **Phased Implementation**: The project is clearly divided into two phases, with Phase 1 handling data processing and indexing, and Phase 2 implementing the agentic RAG logic.

2. **Minimal Directory Structure**: The codebase has a flat structure with a single subdirectory for Phase 1, suggesting a focused, single-purpose application.

3. **Runtime-Generated Directories**: The code references directories (`/cache`, `/docs`) that are created during runtime rather than being part of the repository structure.

4. **Clear File Naming**: Files are named according to their purpose in the pipeline (e.g., `phase1_build.py`, `agentic_rag_phase2.py`).

5. **Modular Design**: Both phases are implemented as standalone scripts that can be run independently, with Phase 2 depending on the artifacts generated by Phase 1.

## Details
The codebase follows a sequential processing pipeline:
1. Phase 1 (`phase1_build.py`) processes documents to create indexes:
   - Document extraction from PDFs
   - Paragraph-level chunking
   - Embedding generation
   - FAISS (vector) and BM25 (keyword) index creation

2. Phase 2 (`agentic_rag_phase2.py`) implements the intelligent query processing:
   - Query classification (Irrelevant, General Q&A, Company-Specific)
   - Hybrid retrieval from internal documents
   - Answer generation from context
   - Internet search fallback
   - Redis-based caching for similar queries
   - Confidence scoring for generated answers

The organization reflects a mature, production-ready application with a clear separation of concerns between data processing and query handling components.
