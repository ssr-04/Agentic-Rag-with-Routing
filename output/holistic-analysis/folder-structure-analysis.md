# Folder Structure Analysis Report

## Summary
The codebase implements a two-phase Agentic Retrieval-Augmented Generation (RAG) system with a clear separation of concerns between data processing/indexing (Phase 1) and intelligent query handling (Phase 2). The folder structure is minimal but well-organized, with a clear progression from data preparation to advanced RAG functionality. The system features a hybrid search approach combining semantic (FAISS) and keyword (BM25) search, with Redis-based caching for performance optimization.

## Directory Layout
- `/`: Root directory containing the main Phase 2 implementation and documentation
  - `Phase-1/`: Contains the data ingestion, preprocessing, and index building script
  - `README.md`: Comprehensive documentation of the system's features and usage
  - `agentic_rag_phase2.py`: Core logic for the intelligent agent's query processing

## Observed Patterns

### Code Organization Pattern
The codebase follows a logical progression from data preparation to intelligent query handling:
1. **Phase 1** (in `Phase-1/phase1_build.py`): Data ingestion, chunking, and index building
2. **Phase 2** (in `agentic_rag_phase2.py`): Intelligent query processing, retrieval, and response generation

### Modular Code Structure
Both Phase 1 and Phase 2 scripts are organized with a clear separation of concerns:
- **Configuration**: Constants and environment variables at the top
- **Utility Functions**: Helper methods for common operations
- **Core Functionality**: Specialized functions for each processing step
- **Orchestration**: Functions that coordinate the overall workflow
- **CLI Interface**: Command-line entry point with argument parsing

### Dependency Management
The project uses standard Python practices for dependency management:
- `.env` file for API keys and configuration (referenced but not included in the repo)
- Implicit `requirements.txt` mentioned in README but not present in the repository
- Explicit imports at the top of each file

## Details

### Phase 1: Data Processing & Indexing
The `Phase-1/phase1_build.py` script handles:
- PDF document extraction with paragraph-level chunking
- Text cleaning and normalization
- Embedding generation using Google's Gemini API
- Hybrid index building (FAISS for semantic search, BM25 for keyword search)
- CLI interface for building indexes and basic querying

Key outputs stored in a `cache/` directory (not shown in repo):
- `cache/faiss_index.bin`: FAISS vector index for semantic search
- `cache/faiss_metadata.json`: Metadata mapping index IDs to chunk info
- `cache/bm25_index.pkl`: Serialized BM25 index for keyword search
- `cache/chunks.json`: Extracted and processed text chunks

### Phase 2: Intelligent Query Processing
The `agentic_rag_phase2.py` script implements:
- Query classification (Irrelevant, General Q&A, or Company-Specific)
- Hybrid retrieval combining semantic and keyword search
- LLM integration with Google's Gemini for various reasoning tasks
- Internet search fallback via Serper AI
- Confidence scoring for generated answers
- Redis-based caching with vector similarity for performance optimization
- CLI interface for interactive querying

### Missing Directories
The codebase references but does not include:
- `docs/`: Expected to contain PDF documents for ingestion
- `cache/`: Generated by Phase 1, stores indexes and processed data

### Configuration
Both phases use environment variables loaded from a `.env` file (not included in the repo):
- `GEMINI_API_KEY`: Required for LLM interactions
- `SERPER_API_KEY`: Optional for internet search fallback
- Redis configuration variables: `REDIS_HOST`, `REDIS_PORT`, `REDIS_DB`, `REDIS_PASSWORD`
